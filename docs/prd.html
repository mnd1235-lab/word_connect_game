01 개요

끝말잇기 대전은 모바일 웹에서 열리는 한국어 끝말잇기 게임이다. 한 기기에 둘러앉은 2~4명이 차례로 단어를 입력하면, 앱이 표준국어대사전 표제어를 기준으로 즉시 판정하고 타이머를 넘긴다.

MVP는 설치 없이 링크만으로 시작되는 로컬 동일 기기 대전 한 가지에 집중한다. 서버 대전·계정·랭킹은 이번 범위에 넣지 않는다. 판정 로직과 사전 데이터를 클라이언트에 완결시켜 두면, 이후 온라인 대전을 얹을 때 규칙 엔진을 그대로 재사용할 수 있다.

사과 → 과일 → 일기 → 기차

기본 규칙 — 앞 단어의 마지막 음절로 시작하는 명사를 잇는다. 이어갈 단어를 못 내면 탈락.

02 배경과 문제

끝말잇기는 준비물이 필요 없는 대신 판정에서 게임이 멈춘다. 오프라인에서 벌어지는 문제는 대체로 세 가지다.

  • 사전 다툼 — "그런 단어가 어디 있어"로 흐름이 끊긴다. 누군가 검색하는 동안 판이 식는다.
  • 규칙 불일치 — 두음법칙을 허용할지, 한 글자 단어를 인정할지가 매번 즉흥적으로 정해진다.
  • 기록 부재 — 이미 쓴 단어를 아무도 정확히 기억하지 못해 중복이 그냥 지나간다.

기존 끝말잇기 앱 대부분은 AI 대전이나 온라인 매칭에 집중해, 정작 사람들이 실제로 노는 상황 — 한 테이블에 모여 폰 하나를 돌리는 상황 — 을 비워 두고 있다. 이 제품은 그 자리를 노린다.

03 목표 · 비목표

목표

  • 링크 진입 후 15초 안에 첫 판이 시작된다.
  • 판정은 사람이 개입할 여지 없이 즉시, 그리고 사유와 함께 내려진다.
  • 규칙(두음법칙·시간·한방단어)은 판 시작 전에 명시적으로 합의된 상태로 고정된다.
  • 비행기·지하철에서도 동작한다 — 사전이 기기 안에 있다.

비목표

  • 회원가입·로그인·프로필
  • 온라인 실시간 매칭과 서버 권위 판정
  • AI 상대 대전 및 난이도 조절
  • 전역 랭킹, 시즌, 재화·과금
  • 한국어 외 언어 지원
범위 판단 기준

MVP에서 어떤 기능을 넣을지 다툴 때는 "이게 없으면 둘러앉은 네 명이 한 판을 끝까지 못 하는가"를 묻는다. 아니라면 다음 버전이다.

07 게임 규칙 명세

규칙은 제품의 핵심이자 분쟁의 원천이다. 아래 명세는 구현과 QA의 단일 기준이며, 화면에도 같은 문장으로 노출한다.

7.1 진행과 승패

  • 첫 플레이어는 무작위로 정해지며, 시스템이 2음절 이상 제시어를 하나 띄우고 시작한다.
  • 차례가 된 플레이어는 제한 시간 안에 유효한 단어를 제출한다.
  • 제한 시간 초과, 또는 3회 연속 무효 입력 시 해당 플레이어 탈락.
  • 마지막 한 명이 남으면 그 플레이어가 승리한다. 2인전은 첫 탈락이 곧 패배다.
  • 탈락자는 이후 턴에서 자동으로 건너뛴다.

7.2 유효 단어 조건

조건내용위반 시 메시지
V1표준국어대사전 표제어에 존재하는 명사사전에 없는 단어예요
V22음절 이상 (한 글자 단어 불가)두 글자 이상이어야 해요

V4이번 판에서 아직 쓰이지 않은 단어이미 나온 단어예요 (3번째 차례)

고유명사, 방언·옛말·북한어, 띄어쓰기가 있는 구(句)는 인정하지 않는다. 사전 인덱스를 만들 때 품사·분류 태그로 걸러 낸다(10장).

7.3 두음법칙

기본값은 허용이다. 앞 단어가 ㄹ 또는 ㄴ으로 시작하는 음절로 끝나면, 두음법칙을 적용한 음절로 시작하는 단어도 받는다. 변환 규칙은 초성과 중성의 조합으로 결정된다.

끝 음절의 초성중성허용되는 첫 음절예
ㄹㅑ ㅕ ㅖ ㅛ ㅠ ㅣㅇ 으로 교체논리 → 이발소, 강렬 → 열대야
ㄹ그 외 모음ㄴ 으로 교체연락 → 낙엽, 도로 → 노래
ㄴㅑ ㅕ ㅖ ㅛ ㅠ ㅣㅇ 으로 교체남녀 → 여자, 안녕 → 영화
그 외—변환 없음사과 → 과일
연락 → 두음 적용 → 낙엽 또는 락타

허용 모드에서는 원래 음절과 변환 음절을 둘 다 받는다. 엄격 모드를 켜면 변환형을 거부하고, 입력창 힌트도 원래 음절 하나만 보여 준다.

7.4 한방단어

이어갈 표제어가 하나도 없는 꼬리 음절로 끝나는 단어를 한방단어라 한다. 기본값은 금지다 — 판이 한 수에 끝나면 재미가 없다.

  • 한방단어 목록은 손으로 관리하지 않는다. 빌드 시점에 인덱스를 훑어 다음 단어 후보 수가 0인 음절을 자동 산출하고, 두음법칙 설정별로 각각 계산한다.
  • 금지 모드에서 한방단어를 내면 무효 처리하고 "이 단어로는 이어갈 말이 없어요"를 띄운다. 차례는 유지된다.
  • 설정에서 허용하면 즉시 승리로 처리하고, 결과 화면에 한방단어로 끝났음을 표시한다.
결정 필요

후보 수가 1~2개뿐인 사실상 한방단어(예: 특정 인명·전문용어로만 이어지는 음절)를 어떻게 다룰지는 미정이다. 초기에는 0개만 차단하고, 오판정 신고 데이터를 본 뒤 임계치 상향을 검토한다.

08 화면과 플로우

S1홈바로 시작 · 규칙 보기. 직전 설정을 기억해 재시작이 한 번에 된다.
S2판 설정인원 2~4, 이름(선택), 타이머, 두음법칙, 한방단어.
S3대전차례 표시 · 타이머 링 · 단어 체인 · 입력창.
S4결과순위, 총 단어 수, 체인 복기(뜻풀이), 같은 설정으로 재대결.

대전 화면 (S3) 구성

  • 상단 — 현재 차례 플레이어 이름과 순서 표시. 기기를 넘겨받은 사람이 자기 차례임을 0.5초 안에 알아야 한다.
  • 타이머 — 원형 진행 링. 5초 이하에서 색이 주색으로 바뀌고 진동이 한 번 울린다. 소리는 기본 꺼짐.
  • 중앙 — 단어 체인. 최신 단어가 가장 크고, 이어야 할 음절이 강조된다. 가로 스크롤로 지난 단어를 되짚을 수 있다.
  • 하단 — 입력창과 제출 버튼. 포커스는 차례 전환과 동시에 자동으로 잡히고, 한글 IME 조합 중에는 제출을 막는다.
  • 무효 입력 — 입력창이 짧게 흔들리고 사유 문구가 뜬다. 남은 시도 횟수를 함께 보여 준다.
인터랙션 원칙

기기를 넘기는 동작이 곧 턴 전환이다. 전환 애니메이션은 0.3초를 넘기지 않고, prefers-reduced-motion에서는 즉시 전환한다.

10 사전 데이터와 판정 엔진

10.1 원천 데이터

국립국어원 표준국어대사전 표제어를 기준으로 하되, 배포 형태는 정적 인덱스다. 런타임에 외부 API를 호출하지 않는다 — 응답 지연이 게임 리듬을 깨고, 오프라인에서 죽는다.

  • 표제어 중 명사만 추출하고, 고유명사·방언·옛말·북한어·구(句)를 제외한다.
  • 2음절 이상, 한글 음절로만 구성된 것만 남긴다.
  • MVP 목표 규모는 8만~12만 어휘. 전체 표제어를 다 넣으면 초성 조합만 아는 사람이 이기는 게임이 된다.
  • 뜻풀이는 첫 번째 어의 한 줄만 저장한다(FR-09용).

10.2 인덱스 구조

  • 첫 음절 기준 샤딩 — words/가.json 형태로 나눠, 필요한 샤드만 지연 로딩한다.
  • 판정용 Set — 첫 진입 시 전체 표제어 해시를 하나의 압축 파일로 받아 Set에 올린다. 조회는 O(1).
  • 꼬리 음절 통계 — 음절별 후보 수를 미리 계산해 한방단어 판별과 힌트에 쓴다. 두음 허용/엄격 두 벌을 만든다.
  • 모든 인덱스는 빌드 타임에 생성되며, 생성 스크립트와 원천 스냅샷 버전을 저장소에 남긴다.

10.3 판정 순서

  1. 입력 정규화 — 앞뒤 공백 제거, NFC 정규화, 한글 음절 외 문자 검사(V5)
  2. 길이 검사(V2)
  3. 연결 검사 — 필요 음절 집합 계산 후 대조(V3, 두음법칙 포함)
  4. 중복 검사(V4)
  5. 사전 조회(V1)
  6. 한방단어 정책 적용(7.4)

사유 표시는 이 순서를 따른다. 여러 조건을 동시에 어겨도 먼저 걸린 하나만 알려 준다 — 한 번에 두 가지를 지적하면 아무것도 전달되지 않는다.

사전 확보가 선행 과제

표준국어대사전·우리말샘 데이터는 이용 조건이 서로 다르고, 우리말샘은 저작자 표시 조건이 붙는다. 개발 착수 전에 라이선스와 출처 표기 문안을 확정해야 하며, 이 결과에 따라 어휘 규모와 뜻풀이 제공 여부가 달라질 수 있다. 확정 전까지는 자체 정제한 소규모 어휘 목록으로 엔진을 개발한다.

11 비기능 요구사항

영역요구사항
성능판정 p95 < 50ms. 초기 로딩 LCP < 2.5초(4G, 중급 안드로이드). 사전 초기 다운로드 압축 후 2MB 이하.
오프라인PWA. 최초 로딩 이후 네트워크 없이 전체 게임 플레이 가능.
대응 기기iOS Safari 16+, Android Chrome 최근 2개 버전. 세로 360px 폭 기준 설계, 가로 모드는 레이아웃만 대응.
접근성본문 대비 4.5:1 이상. 판정 결과는 색만이 아니라 아이콘과 문구로도 구분. 타이머 경고는 시각·진동 병행. 스크린 리더로 현재 차례와 이어야 할 음절을 읽을 수 있어야 한다.
입력한글 IME 조합 중 제출 차단, 자동완성·자동수정 비활성화, 엔터 제출 지원.
개인정보계정 없음. 플레이어 이름은 기기 내에만 저장하고 전송하지 않는다. 익명 이벤트는 판 설정·결과·판정 지연 등 입력 단어를 제외한 집계값만 수집한다. 단, 오판정 신고(FR-10)는 해당 단어를 함께 보낸다.
언어UI 문구는 한국어 단일. 문구는 코드에서 분리해 ko.ts로 관리한다.

12 기술 구조

  • 프런트엔드 — React + TypeScript, Vite 빌드. 정적 호스팅(Vercel/Cloudflare Pages)으로 배포하고 백엔드를 두지 않는다.
  • 상태 — 게임 상태는 순수 리듀서 하나로 관리한다. (state, action) → state 형태라 규칙 검증을 UI 없이 단위 테스트할 수 있고, v2에서 서버로 그대로 옮길 수 있다.
  • 규칙 엔진 — packages/rules로 분리. UI·DOM·타이머에 의존하지 않는 순수 모듈.
  • 사전 — packages/dict. 빌드 스크립트, 정적 인덱스, 조회 API.
  • 영속화 — 진행 중 판과 직전 설정은 localStorage에 저장. 사전 샤드는 Cache Storage.
  • 테스트 — 규칙 엔진은 규칙표(V1~V5, 두음법칙 조합)를 그대로 옮긴 테이블 기반 테스트로 덮는다. 두음법칙 케이스는 전수 검증한다.
